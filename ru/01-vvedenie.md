# Введение

Давайте рассмотрим несколько ситуаций:

- Из своей новостной ленты вы узнаете, что вышла новая версия Spring. Чтобы узнать подробности, вы просите LLM дать краткое описание новой версии, однако в ответ слышите, что такой версии не существует!
- К вам пришла задача разобраться с тормозами БД. Вы спрашиваете у LLM возможные причины, а затем просите проверить все варианты конкретно на вашей БД, однако LLM отвечает, что она это не умеет (может, это и к лучшему).

Обе проблемы — от одного корня: LLM изолирована от внешнего мира. Ей нужен контролируемый способ вызывать функции и получать живые данные.

Традиционно это решали через function calling — механизм, при котором описание функций встраивается прямо в запрос к LLM. Но этот механизм каждый провайдер реализовывал по-своему, а инструменты были намертво прибиты к конкретному приложению. Переиспользовать их в другом клиенте без переписывания — невозможно. Пока Anthropic не показала миру открытый протокол MCP.

**Model Context Protocol (MCP)** — открытый стандарт, который описывает клиент-серверный протокол: сервер предоставляет инструменты, ресурсы и промпты, а любой MCP-совместимый клиент может их использовать. Один сервер — любые клиенты.

**Spring AI 2.0** делает интеграцию с MCP тривиальной для Java-разработчика. Аннотации `@McpTool` и `@McpToolParam` превращают метод в инструмент, доступный LLM. `@McpResource` и `@McpPrompt` — в живые данные и готовые сценарии. Автоконфигурация Spring Boot скрывает транспортный слой, а на стороне MCP-клиента `ChatClient` автоматически регистрирует удалённые инструменты как function callbacks.

Статья предполагает знание Spring Boot и базовое понимание LLM.

Мы разберём архитектуру MCP, разложим по полочкам три ключевых концепта — Tool, Resource и Prompt — и напишем работающий MCP-сервер на Spring Boot с нуля.
