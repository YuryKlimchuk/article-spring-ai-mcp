# Введение

Современные LLM обучены на огромных массивах данных, но их знания заморожены на момент обучения. Спросите ChatGPT о медленных запросах в вашей production-базе — и он честно ответит: «Я не имею доступа к вашей инфраструктуре». И это правильно: давать LLM прямой доступ к базам данных, API и файловой системе — опасная практика, которая противоречит любому security-регламенту.

Проблема, однако, глубже. Даже если вы решите дать LLM контролируемый доступ к внешним системам, вы столкнётесь с дублированием. Представьте: вы написали сервис, который подключается к PostgreSQL и анализирует `pg_stat_statements`. Чтобы Claude Desktop мог этим пользоваться, вы переписываете логику ещё раз — на JavaScript или Python. Чтобы GitHub Copilot — третий раз, уже под его протокол. Инструменты прибиты к хосту и не переиспользуются.

Традиционно эту задачу решали через function calling — механизм, при котором описание функций встраивается прямо в запрос к LLM. OpenAI, Anthropic, Google — у каждого свой формат, свои ограничения, и инструменты живут внутри конкретного приложения. Это работает для одного чат-бота, но не для экосистемы.

**Model Context Protocol (MCP)** — открытый стандарт от Anthropic, который решает обе проблемы. MCP описывает клиент-серверный протокол: сервер предоставляет инструменты, ресурсы и промпты, а любой MCP-совместимый клиент может их использовать. Один сервер — любые клиенты. LLM видит только разрешённые операции, а не сырой доступ к базе.

**Spring AI 2.0** делает интеграцию с MCP тривиальной для Java-разработчика. Аннотации `@McpTool` и `@McpToolParam` превращают метод в инструмент, доступный LLM. `@McpResource` и `@McpPrompt` — в живые данные и готовые сценарии. Автоконфигурация Spring Boot скрывает JSON-RPC транспорт, а на стороне MCP-клиента `ChatClient` автоматически регистрирует удалённые инструменты как function callbacks.

Статья предполагает знание Spring Boot и базовое понимание LLM. Мы разберём архитектуру MCP, разложим по полочкам три ключевых концепта — Tool, Resource и Prompt — и напишем работающий MCP-сервер на Spring Boot с нуля. Вы увидите, как один и тот же код обслуживает и чат-интерфейс, и Claude Desktop, и любой другой MCP-клиент.
